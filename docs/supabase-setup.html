Vier stappen. Daarna bewaart de bouwer elke nieuwsbrief online, kun je er vanaf elke computer bij, en werkt de HTML die je naar Mailchimp plakt inclusief foto's.

Belangrijk: voer de stukken code hieronder apart uit. De SQL-editor draait alles als één geheel — als het tweede stuk struikelt, wordt het eerste ook weer teruggedraaid.
01

De tabel voor de nieuwsbrieven

Open in Supabase de SQL Editor, klik New query, plak dit en klik Run. Je hoort Success. No rows returned te zien.

create table if not exists public.nieuwsbrieven (
  id          uuid primary key default gen_random_uuid(),
  naam        text not null,
  merk        text not null default 'nbc',
  blokken     jsonb not null default '[]'::jsonb,
  verwijderd  boolean not null default false,
  bijgewerkt  timestamptz not null default now()
);

alter table public.nieuwsbrieven enable row level security;
grant all on table public.nieuwsbrieven to anon, authenticated;

drop policy if exists "bouwer toegang" on public.nieuwsbrieven;
create policy "bouwer toegang" on public.nieuwsbrieven
  for all to anon, authenticated
  using (true) with check (true);

notify pgrst, 'reload schema';
02

De map voor de foto's

Doe dit via de knoppen, niet via SQL — dat werkt betrouwbaarder. Ga naar Storage in de linkerbalk en klik New bucket:

Namenieuwsbrief
Public bucketaanzetten — anders kan Mailchimp de foto's niet laden

Daarna moet de bouwer er foto's in mogen zetten. Open opnieuw de SQL Editor met een nieuwe query, plak dit en klik Run:

drop policy if exists "nieuwsbrief beeld lezen"     on storage.objects;
drop policy if exists "nieuwsbrief beeld toevoegen" on storage.objects;
drop policy if exists "nieuwsbrief beeld bijwerken" on storage.objects;

create policy "nieuwsbrief beeld lezen" on storage.objects
  for select to anon, authenticated
  using (bucket_id = 'nieuwsbrief');

create policy "nieuwsbrief beeld toevoegen" on storage.objects
  for insert to anon, authenticated
  with check (bucket_id = 'nieuwsbrief');

create policy "nieuwsbrief beeld bijwerken" on storage.objects
  for update to anon, authenticated
  using (bucket_id = 'nieuwsbrief');

Loopt dit vast op must be owner of table objects? Geen probleem — je tabel uit stap 1 blijft gewoon staan. Zet de rechten dan via Storage → Policies met de knoppen.

03

De sleutel in de bouwer zetten

Ga in Supabase naar Settings → API en kopieer de anon public key. Zet die in config.js in de repository:

window.NBC_CONFIG = {
  url: 'https://uqgpcvuhwfvyhvxokptn.supabase.co',
  key: 'eyJhbGciOi...'   // anon / publishable key
};

Commit en push — daarna werkt het voor iedereen die de bouwer opent, zonder dat er nog iets ingevuld hoeft te worden.

Deze sleutel hoort in de browser thuis: hij staat in elke Supabase-webapp en geeft alleen toegang tot wat de policies hierboven toestaan. Zet er nooit de service_role-key neer.

04

Controleren of alles staat

Plak deze query in de SQL-editor. Je ziet in één regel of de tabel, de fotomap én de policies er zijn:

select
  (select string_agg(tablename, ', ')
     from pg_tables
    where schemaname = 'public'
      and tablename = 'nieuwsbrieven')        as tabel,
  (select name || case when public then' (public)'else' (NIET public!)'end
     from storage.buckets
    where id = 'nieuwsbrief')                 as fotomap,
  (select count(*) from pg_policies
    where tablename = 'objects'
      and policyname like 'nieuwsbrief%')     as beeld_policies;

Je wilt zien: nieuwsbrieven · nieuwsbrief (public) · 3.

Klaar. Testen maar.

Open de bouwer, voeg een blok met een foto toe en upload er een. Sla de nieuwsbrief op onder een naam, herlaad de pagina en open hem opnieuw uit Mijn nieuwsbrieven — staan tekst én foto er nog, dan klopt de hele keten.

Klik daarna op HTML voor Mailchimp. Zie je geen waarschuwing over foto's die nog niet online staan, dan werkt de fotomap ook goed.
